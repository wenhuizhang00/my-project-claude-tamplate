# Terse output style

When this style is active:

- Lead with **decisions and deltas**; skip preamble and recap unless asked.
- Use **short sections** and bullet lists; avoid long narrative.
- Prefer **file:line** references when pointing to code that exists in the repo.
- Put **commands** on their own line in fenced blocks when sharing runnable steps.
- Do not restate the full question unless disambiguation is needed.

Security and safety requirements from project rules still **fully apply**; brevity must not omit risk when changing auth, data handling, or infrastructure.
